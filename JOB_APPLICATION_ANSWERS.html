2. Multi-Tenant Access with Supabase RLS

Row Level Security (RLS) ensures complete tenant isolation at the database level. Each query automatically filters data based on the authenticated user's organization.

Implementation Strategy

-- Organizations: Admins see all, others see only their org
CREATE POLICY "org_access" ON organizations
  FOR ALL USING (
    EXISTS (
      SELECT 1 FROM user_profiles
      WHERE id = auth.uid() 
      AND (role = 'admin' OR organization_id = organizations.id)
    )
  );

-- Sites: Filtered by user's organization
CREATE POLICY "site_access" ON sites
  FOR ALL USING (
    organization_id IN (
      SELECT organization_id FROM user_profiles 
      WHERE id = auth.uid()
    )
    OR EXISTS (
      SELECT 1 FROM user_profiles 
      WHERE id = auth.uid() AND role = 'admin'
    )
  );

-- Documents: Access through site → organization chain
CREATE POLICY "document_access" ON documents
  FOR ALL USING (
    site_id IN (
      SELECT id FROM sites WHERE organization_id IN (
        SELECT organization_id FROM user_profiles 
        WHERE id = auth.uid()
      )
    )
  );

Key Benefits

  • Database-level security: Cannot be bypassed by application bugs
  • Automatic filtering: No need to add WHERE clauses in every query
  • Role hierarchy: Admins bypass restrictions, others are scoped

4. File Security Risks & Prevention

Risk Prevention Strategy
Unauthorized file access Supabase Storage RLS policies linked to user's organization. Files stored in /{org_id}/{site_id}/ structure with policies checking ownership.
Direct URL guessing Use signed URLs with short expiration (e.g., 1 hour) instead of public URLs. URLs are generated server-side after auth check.
Malicious file uploads Validate file types (whitelist PDF, DOC, images), enforce size limits (10MB), scan with antivirus API before storage.
Cross-tenant data leaks Storage bucket policies enforce organization_id matching. Even with valid auth, users can't access other orgs' files.
Missing audit trail Log every upload/download/delete to audit_logs table with user ID, timestamp, IP address, and action details.
Insecure file deletion Soft delete first (mark as deleted), hard delete after retention period. Only admins can permanently delete.

Storage RLS Policy Example

-- Only allow access to files in user's organization folder
CREATE POLICY "org_file_access" ON storage.objects
  FOR ALL USING (
    bucket_id = 'documents' AND
    (storage.foldername(name))[1] IN (
      SELECT organization_id::text FROM user_profiles 
      WHERE id = auth.uid()
    )
  );
